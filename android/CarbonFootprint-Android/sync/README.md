# 家庭碳账户 · 本地同步服务

E1「超级终端多端同步」的中转服务。两台设备（模拟器或真机）都连这台宿主机，
各自上报本机减排快照，再从服务端拉取组内其他成员，实现**真实的跨设备数据合并**。

## 一、启动

```bash
node sync/server.js 8081
```

零依赖，只要有 Node 即可。启动后会打印监听地址与现有家庭组数量。

## 二、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/family/create` | 建组 `{ code, deviceId, name, totalG, balance, weekG }`；邀请码重复返回 409 |
| POST | `/api/family/join` | 加入 `{ code, deviceId, name, ... }`；组不存在返回 404 |
| POST | `/api/family/leave` | 退出 `{ code, deviceId }`；**组内无成员时自动解散** |
| POST | `/api/family/report` | 上报本机快照，返回组内全部成员 |
| GET | `/api/family/members?code=CF123456` | 拉取组内成员 |
| GET | `/api/health` | 健康检查 |

## 三、数据

落盘到同目录 `data.json`（已加入 `.gitignore`），重启不丢组。想重置直接删掉该文件。

## 四、两台设备怎么连

| 设备 | 填什么 |
|---|---|
| **模拟器（默认）** | 不用填，App 自动尝试 `http://10.0.2.2:8081` |
| 真机同一 Wi-Fi | 「设置 → 服务配置 → 家庭同步服务地址」填 `http://<电脑局域网IP>:8081` |

## 五、演示流程

1. 电脑启动 `node sync/server.js 8081`
2. 模拟器 A：家庭碳账户 → 创建家庭组 → 记下邀请码（如 `CF123456`）
3. 模拟器 B：家庭碳账户 → 输入邀请码 + 昵称（如"妈妈"）→ 加入
4. 两边各自录入几条行为，然后点「立即同步」
5. 两台设备的成员列表都会出现对方，家庭累计减排 / 合并积分 / 本周减排同步更新

## 六、离线行为

服务不可达时：
- 建组 / 加入会明确报错（不建"幽灵组"，避免别人加不进来）
- 已有组的设备继续显示**本地缓存**的成员数据，页面标记「离线（显示本地缓存）」
- 服务恢复后点「立即同步」即可拉齐

## 六之二、自动上报

App 里每录入一条行为（手动 / AI / 平台导入），`BehaviorService.submit` 成功后**立即**上报，
不做延迟。若上一次上报还在进行中，则标记"待补一次"，结束后再补发，避免并发堆积。

> 早期版本用 `setTimeout` 做 800ms 防抖，但应用切到后台后定时器会被系统冻结——
> 用户"录完就切到另一台设备"时上报会永远发不出去，所以改成立即上报。

「立即同步」只用于：换设备后首次拉取、或离线恢复后补拉。

## 七、为什么不用分布式软总线

`distributedDataObject` 需要两台设备同账号 + 互信组网 + 软总线发现，而模拟器上：
- QEMU NAT 隔离多播/广播，设备发现不通
- 同机两个 QEMU 实例各自独立 NAT，互相看不见
- 同账号互信在模拟器里做不全

因此采用应用层同步：两台设备都连宿主机服务，数据经 HTTP 中转后合并。
